# 高玥集团 OA 原型升级需求确认稿

日期：2026年10月18日

状态：已于2026年10月18日获用户确认。本稿为本轮原型升级依据；产品代码和网站尚未修改，实施计划另行审阅。

## 本轮目标和边界

升级现有 CEO 工作台原型，让全体员工能够通过演示身份体验日常办公、每日工作安排、成果反馈和分权审批。重点解决口头工作安排容易遗漏、理解偏差、缺少反馈、优先级冲突及成果资料难找的问题。

- 保留中文、深青色风格、二级导航和现有可交互页面，在现有代码上增量升级。
- 全员登录在原型中通过演示账号或身份入口体验。数据继续保存在当前浏览器，不建设真实认证、服务器权限隔离、跨设备同步或正式多人系统。
- 所有预填人员、日期、金额、排班和任务继续显著标注为演示数据。公开演示版本只包含示例，不上传本地浏览器中录入的内容。
- 附件继续使用名称、说明和资料链接展示；本轮不增加真实文件上传下载。已有备份恢复功能保留。
- 设备选择与手机端使用方式暂缓决定，保留现有响应式页面，不在本轮新建移动应用或采集设备、在线时间。
- 本轮处理 OA 工作管理、人事、行政和财务办公流程，不扩展商品采购交易、库存、销售、供应商分佣或门店经营系统。既有业务项目示例保留，不新增业务专属优化。

## 已确认的组织和权限规则

| 角色或关系 | 已确认规则 |
| --- | --- |
| CEO | 定义方向、建设工作与要求；查看全局；与指定负责人共同验收阶段成果。 |
| 总经理 | 具有全公司管理视角；可以与 CEO 一样制定日常任务工作模板，审批仍遵循授权。 |
| 项目负责人 | 自主拆分、分派及调整已授权的项目内部工作；总体目标、关键期限或预算变化提交审批。 |
| 直属主管 | 统一安排下属的跨项目人员投入、工作量和优先级；项目负责人提出支持需求，由直属主管协调。 |
| 全体员工 | 均纳入人员档案，并通过各自演示身份办理个人事务、查看工作待办、反馈和提交成果。重复 SOP 岗位也纳入 OA。 |
| 人事与行政 | 当前同一人兼任，岗位职责和权限独立配置，未来可交接拆分。 |
| 财务 | 独立人员负责财务核对与办理，按授权处理各类申请。 |
| 项目可见性 | 除 CEO、总经理的全公司管理视角外，项目负责人和成员只能查看自己负责或参与的项目。 |
| 敏感信息 | 人事敏感资料、薪酬、财务明细单独授权，不因项目可见或全公司工作总览而自动开放。 |

直属主管、项目负责人、岗位任职和职能权限分别记录，允许一人兼任多项职责。全局工作总览不自动授予所有事项的修改、审批权。

未参与任何项目的员工也可以办理个人事务和查看日常待办；岗位工作与行政申请允许不关联业务项目。

建议用独立的人员支持申请衔接跨项目调配：申请人向直属主管提供必要工作摘要、所需人员或时段、优先级和期限。主管未参与原项目时，只能查看该支持申请及排程所需信息，仍不能打开原项目的完整内容。

## 任务体系和每日工作文档

### 人力资源中的任务管理体系

在人力资源模块内建立统一任务管理入口，包含岗位职责、日常任务模板、非日常任务目录、人员安排、工作日历与排班、执行记录、及时性和成果台账。

统一入口复用原项目任务和审批记录，通过关联引用查看同一事项，不复制出第二套进度。项目内的工作仍由项目负责人推进，跨项目安排由直属主管协调。人事权限与任务内容权限分别校验；人力资源作为入口不意味着每个人事账号自动能查看全部项目内容。

### 日常任务

CEO 或总经理制定、发布和调整岗位工作模板。模板记录工作内容、适用岗位、执行频率、完成要求、提交方式和截止规则。直属主管将适用模板安排到员工，并安排实际日期、班次与优先级。

每次执行形成独立记录，保留当次采用的模板版本、责任人、工作日期、班次、截止时间、反馈和成果。模板后续修改不覆盖历史执行记录。需要影响已经安排的未完成工作时，显示调整范围并记录原因。

日常工作完成方式为：员工提交当日结果后显示“已提交”，由直属主管按员工和工作日批量确认；需要补充的单项退回，其他项正常确认。记录提交与确认时间，避免把尚未检查的提交直接表述为已确认成果。普通日常事项不进入 CEO 阶段共同验收。此项已随整体方案确认。

管理人员按照固定工作日生成任务；仓储与门店人员按照个人排班生成当班任务。跨夜班次作为同一次工作安排处理。休息日和请假期间结合排班及主管处置生成对应记录。

原型通过打开页面、切换演示日期或生成指定日期清单演示任务生成，同一人员、模板和执行周期不会因刷新而重复生成。不会暗示关闭页面后仍有服务器定时生成任务。

### 非日常任务

包含项目建设、创新改进、临时事项等工作，保留负责人、期限、交付要求、依赖、优先级、进展、成果与验收记录。

项目继续区分两类大阶段：零到一基础建设期，以及重复基本运作与创新阶段。它们是项目的管理属性，与现有目标、关键结果、里程碑和子任务并存；不同项目可以处于不同阶段。

非日常工作可安排在某一天推进，每日清单引用原任务；当天安排不另造一份独立的项目任务，也不把当天完成一个步骤当作整个任务完成。

无项目归属的临时非日常工作，关联部门或岗位，由直属主管安排并检查，沿用同一任务记录。安排人、责任人、直属主管、被明确指定的协作者及全局管理者按职责查看；敏感材料继续单独授权。此项已随整体方案确认，不为挂接临时工作而创建虚设业务项目。

### 每日待办文档

员工工作入口以日期为中心，明确区分“日常任务”和“非日常任务”。每行直接展示内容、完成要求、优先级、截止时间、当前状态及反馈入口，能够打开对应成果、讨论和变更记录。

直属主管可以在权限范围内直接管理下属工作清单。CEO、总经理可以管理任务标准并查看全局安排。原有待审批、待办理、待验收事项继续进入统一待办，保持事项类型清楚。

原有私人待办保留私密性，单独展示。不会迁移为主管可见的工作事项，也不自动纳入绩效记录。

## 推进 汇报和验收

系统根据实际记录汇总进展、未更新事项、逾期、障碍、待决策和待验收成果。负责人补充异常、下一步和需要决定的事项，不要求所有人另外提交固定日报。

负责人先检查普通子任务，再汇总阶段成果。CEO 与指定负责人共同验收阶段成果，重点任务可以单独提交。修改意见关联原事项并形成后续整改安排，保留成果和各次反馈。

共同验收具体规则为：指定双方分别确认，双方通过后标记已验收；任一方要求修改时进入整改；成果发生修改后重新提交。指定负责人必须是另一位明确的人员。此规则已随整体方案确认。

## 及时性和实际成果

绩效记录仅包含及时性与实际成果，不增加质量评分或按任务数量生成员工排名。原有工作量复杂度仍只用于安排工作，不成为绩效分数。

- 及时性：保留原计划截止时间、经授权调整后的期限、成果提交时间、是否按时、逾期时长和调整依据。
- 实际成果：记录完成说明、交付物说明或资料链接、关联任务和验收记录。
- 员工在周五截止前提交、管理者周一验收时，提交及时性仍按周五判断，验收等待时间单列。
- 退回补充时，保留首次提交、各次补交时间及原因。建议将补交及时性单独展示，不抹除首次记录，不把等待验收时间算作员工提交逾期。
- 日常执行记录和非日常成果分别展示，汇总数能够点击回到原事项，避免把项目父任务、子任务和当日安排重复统计为同一成果。

## 排班 请假与跨时区

全员可办理请假、出差、调休、入职、转岗、离职、工作交接和资产事项。日常人事行政申请分权审批，审批通过后继续完成实际办理，最终记录办结。

请假或出差获批后，列出受影响的日常与非日常工作，由直属主管逐项或批量选择代办、调整期限或本次免执行。保留原责任人、代办人、原期限、调整后期限、原因及关联申请。本次免执行单列，后续周期照常依据工作安排生成。

员工所在国家或地区对应工作时区。固定工作日、班次和日常任务按所在地日期处理。跨地区共同任务共用同一个截止时刻，各人看到当地换算时间及明确时区；CEO 总览统一汇总并保留当地工作日期。时区规则应使用地区时区，不能把中国和美国的时间差写成全年固定值。

原型提供可核对的演示日期和时间，说明当前模拟的时刻及时区；提醒在页面内演示，不发送真实邮件、短信或后台推送。

## 财务办公

四类流程全部纳入：费用报销、借款与备用金、付款申请、预算申请与调整。

申请人填写用途、金额、币种和依据；对应负责人确认需求与归属；财务核对资料和预算，并登记发放、付款、归还或核销等办理结果。审批通过与实际办结分开记录，不触发银行支付。

额度内分权处理，超额度、超预算或特殊事项上报 CEO 或授权审批人。具体额度、审批人、币种和适用范围通过演示规则配置，不虚构已获公司正式授权的数值。

沿用已有审批轨迹、退回重提、代审与催办机制。审批规则需要从固定人员扩展到可匹配当前主管或职能任职人员；具体申请保留当时审批链和规则版本。人员变动时提示处理未完成事项。

预算和实际办理记录建立关联，币种分别展示，不直接混算。原有应收应付示例保留作为已有数据，不在本轮扩建交易、会计或收付款业务系统。

## 行政资产 通知和资料

行政继续管理办公设备台账、领用、借还、维修、采购。相关事项沿用申请、审批、办理、办结和必要的接收确认，保留资产与持有人员记录。

重要制度、工作要求和普通通知区分处理。重要内容指定部门、岗位或人员接收，记录具体发布版本、生效时间、阅读期限及确认时间；未确认事项进入员工提醒和直属主管跟进列表。普通通知无需逐人确认。

制度与模板集中查阅，旧版本保留。升级版本后按新版本接收范围确认，不把旧版本已阅冒充新版本确认。成果和讨论留在对应任务或申请中，继承其可见权限。

## 原型完成时需要演示通过的场景

1. CEO 或总经理发布日常模板；直属主管安排到人；员工打开当日清单并提交成果。
2. 同一员工兼任人事行政两个岗位；后续拆分岗位时移交未完成工作并保留历史人员记录。
3. 固定工作日与轮班产生不同的当班待办；跨夜班次记录一致；刷新不重复生成任务。
4. 非日常任务同时出现在原项目和当天安排中，更新后两处一致，成果不会重复统计。
5. 项目负责人提出跨项目支持需求，直属主管确认人员和优先级；相关方收到对应待办。
6. 普通员工只看到本人相关工作和事务；项目参与者仅查看授权项目；CEO、总经理查看全局工作，敏感资料仍需要单独授权。
7. 普通子任务由负责人检查，阶段成果由 CEO 与指定负责人共同验收；退回、补交和再次验收可以完整走通。
8. 截止前提交、截止后验收仍显示按时提交；补交和获批调整保留记录，页面不存在质量评分。
9. 请假或出差获批后，主管分别演示代办、延期、免执行，员工清单和统计同步变化。
10. 中美两个时区分别查看同一截止事项，显示当地时间但及时性结论一致。
11. 四类财务申请分别走通额度内审批、超额度或超预算升级、财务办理和必要的归还核销。
12. 重要通知确认已阅后从对应待办移除；主管可查看未确认直属员工；新版本重新确认；普通通知无需逐人确认。
13. 旧版本地演示数据升级后保留，刷新仍能恢复，错误输入和越权操作有明确反馈。

14. 无项目成员能够正常办理个人办公事项；直属主管通过支持申请协调下属的外部项目工作，不能因此读取未参与项目的详情。

15. 日常清单可以按日批量确认、单项退回；无项目临时工作可以独立安排、提交、检查，且保持对应可见范围。

## 待配置值与本轮交付

真实人员名单、部门岗位名称、工作时间、班次、地点时区、授权额度、具体审批人和提醒间隔先作为可编辑演示配置，数值不代表公司正式制度。设备使用方式继续待定。

随本稿一并确认的默认规则是：日常成果由直属主管按日批量确认；阶段共同验收双方均确认后通过；主管通过独立支持申请获得跨项目排程所需信息；无项目临时事项归属部门或岗位。

建议按依赖分三批实现和验收：先完成组织岗位与日常模板、每日待办；再接通主管调配、排班请假、共同验收和成果台账；最后完善财务办公、公告跟进、全局汇总和完整回归。这是同一轮已列范围的分批落地，不缩减其他已确认模块。

本轮预期交付为升级后的可交互原型、示例场景、使用说明、验证结果和更新的源码包。沿用现有演示站点发布方式时，仅发布演示内容。产品代码修改与网站更新将在用户确认本稿及后续实施安排后开始。
